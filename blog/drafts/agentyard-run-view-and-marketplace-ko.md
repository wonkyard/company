# 픽셀 사무실 안에서 Claude Code를 직접 돌리기까지, 그리고 마켓플레이스에 올렸습니다

> WONKYARD devlog 3편입니다. 2편에서 예고한 대로, 사무실 뷰를 떠나지 않고 패널 안에서 바로 Claude Code에 일을 시키는 기능을 만들었습니다. 처음엔 헤드리스 피드로 시작했다가, 결국 웹뷰 안에 진짜 터미널을 심는 데까지 갔습니다. 그 사이에 Windows에서 원격 코드 실행 취약점 하나, 죽어도 안 사라지는 좀비 에이전트, 그리고 "부서를 만들어놨는데 그 부서가 일하는 게 화면에 안 보이는" 문제를 만났습니다. 마지막엔 v1.0.0으로 VS Code 마켓플레이스에 올렸습니다.

## 지난 이야기

[2편](https://velog.io/@hyeokkiyaa/Temp-Title)에서 에이전트 회사를 Agentyard라는 VS Code 익스텐션으로 옮겼습니다. 부서마다 방, 에이전트마다 스프라이트, 일하면 책상에 앉고 놀면 돌아다니는 픽셀 사무실입니다. v0.3에서 라이브 레이어를 SQLite 폴링에서 Claude Code 훅으로 바꿔서, 제 회사뿐 아니라 아무나 설치해도 자기 세션의 에이전트가 움직이는 게 보이게 만들었습니다.

2편은 이렇게 끝났습니다.

> 계속 하고 싶어지는 게 하나 있습니다. 패널 안에 입력창을 두고 거기서 Claude Code 자체를 실행해서, 답변을 리포트 피드로 스트리밍해서 받는 것. 그게 3편입니다.

그래서 그걸 만들었습니다.

## v0.4 — 패널에서 Claude Code 실행하기

헤더에 토글을 하나 더 달았습니다. **Office** / **Run**. Run 뷰는 입력창 하나와 스크롤되는 피드 하나입니다. 프롬프트를 보내면 익스텐션이 워크스페이스 루트에서 자식 프로세스를 띄웁니다:

```
claude -p "<프롬프트>" --output-format stream-json --verbose
```

`--output-format stream-json`은 NDJSON을 뱉습니다. 한 줄에 JSON 객체 하나씩. 익스텐션이 그걸 파싱해서 피드 아이템으로 렌더링합니다. 내 프롬프트, 어시스턴트 텍스트, 툴 호출은 압축된 한 줄(`→ Bash: npm test`), 툴 결과, 그리고 턴 수와 소요 시간이 적힌 마지막 요약.

**왜 Agent SDK가 아니라 CLI인가.** 이게 핵심 설계 결정이었습니다. Agent SDK를 쓰면 API 키가 필요하고, 토큰이 미터링됩니다. CLI는 사용자가 이미 `claude`로 로그인해둔 걸 그대로 씁니다. API 키도, 별도 과금도 없습니다. 익스텐션을 깐 사람이 이미 Claude Code를 쓰고 있다면, Run 뷰는 추가 비용 0으로 그냥 됩니다. 그래서 헤드리스 CLI를 자식 프로세스로 띄우는 쪽을 골랐습니다.

한 번에 한 실행만. **Cancel** 버튼은 프로세스 트리 전체를 죽입니다(Windows는 `taskkill /T`, 나머지는 프로세스 그룹 시그널). **New thread**는 새 대화를 시작하고, 아니면 매 메시지가 `--resume`으로 같은 스레드를 잇습니다.

그리고 재밌는 시너지가 하나 있습니다. 이렇게 띄운 `claude`는 설치된 훅을 그대로 상속받기 때문에, 그놈의 활동도 오피스 뷰에 라이브 방으로 뜹니다. Run 뷰에서 일을 시키면 Office 뷰에서 그게 움직이는 게 보입니다. 이건 버그가 아니라 의도한 겁니다.

## 릴리스 게이트가 이걸 막았습니다 — cmd.exe RCE

Agentyard는 회사 파이프라인의 `security-reliability` 게이트를 거칩니다. v0.4 첫 리뷰는 **FAIL**이었고, 이유가 정당했습니다.

Windows에서 `claude`는 보통 npm으로 깔린 `claude.cmd` 배치 런처입니다. 자식 프로세스로 `.cmd`를 실행하면 Node는 `cmd.exe`를 통해 실행합니다. 그리고 **`cmd.exe`에 인자를 안전하게 넘기는 방법은 없습니다.** 따옴표 규칙이 망가져 있어서, 프롬프트에 이런 게 들어 있으면:

```
refactor x" & echo OWNED > C:\pwned.txt & rem
```

`&`가 명령 구분자로 먹혀서 `echo`가 실제로 실행됩니다. 사용자가 붙여넣은 프롬프트 한 줄이 임의 명령 실행이 됩니다.

해결책은 **`cmd.exe`를 아예 안 거치는 것**이었습니다. Windows에서 `.cmd`/`.bat` 런처를 만나면, Agentyard는 그 배치 파일을 열어서 그게 실제로 무엇을 실행하는지 알아냅니다 — `node "C:\...\cli.js"` 형태거나, 번들된 `.exe`거나. 그리고 그 진짜 실행 파일을 `shell` 없이 argv 배열로 직접 spawn합니다. 그러면 프롬프트가 `CreateProcess`로 글자 그대로 전달되고, 해석할 셸 자체가 없습니다.

```js
// shared/winWrap.js — .cmd/.bat 런처를 진짜 exe로 해석. 못 알아보면 거부(null),
// 절대 cmd.exe로 안 넘김.
function resolveLauncher(cmdPath) { /* node-forwarding 또는 exe-forwarding shim */ }
```

알아볼 수 없는 `.cmd`는 그냥 거부합니다. 셸에 태우느니 안 도는 게 낫습니다. 지금 이걸 검증하는 테스트가 있는데, 적대적인 프롬프트를 넣고 자식이 그걸 **한 개의 argv 원소로 글자 그대로** 받았는지, 그리고 주입된 명령이 실행 안 됐는지(`PWNED.txt`가 안 생겼는지) 확인합니다.

## 좀비 에이전트

또 하나. 오피스 뷰가 훅 이벤트로 라이브 방을 그리는데, `SubagentStop`이나 `Stop`을 받으면 그 에이전트가 사라집니다. 그런데 VS Code를 실행 도중에 강제 종료하면? 그 이벤트가 영영 안 옵니다. 사무실에 죽지 않는 스프라이트가 남습니다.

`agentyard.staleMinutes`(기본 15분)를 추가했습니다. 종료 보고를 한 적 없고 그 시간만큼 아무 활동도 없는 라이브 에이전트는 좀비로 취급해서(그 VS Code가 실행 도중 강제 종료된 것) 씬에서 빼버립니다. `0`으로 두면 이 검사를 끕니다.

## v0.4.1 — 피드 잔버그

패키징하고 실제로 써보니 세 가지가 나왔습니다. 끝난 실행이 답변을 두 번 찍던 것(마지막 줄을 요약으로 바꿈 — `done · N turns · 걸린 시간`, 답변은 위에 스트리밍된 줄로 유지). `claude` 시스템 레코드마다 `session <id>` 줄이 하나씩 찍히던 것(실행당 한 번으로). 그리고 `claude -p`가 "no stdin data received in 3s"를 계속 출력하던 것 — 자식 stdin을 spawn 시점에 닫아서 해결.

## v0.5 — 헤드리스로는 부족했습니다

`claude -p`는 원샷입니다. 비대화형. 즉:

- 권한 프롬프트에 답할 수 없습니다. 헤드리스 `-p`는 프롬프트를 띄울 수가 없어서, 툴을 미리 `settings.json`이나 `--allowedTools`로 허용해둬야 합니다.
- plan 모드가 없습니다.
- 진짜 왕복 대화가 안 됩니다. 매번 `--resume`으로 새 원샷을 겁니다.

Run 뷰에서 실제로 일을 시켜보니 이게 답답했습니다. 그래서 v0.5에서 Run 뷰를 **진짜 터미널**로 바꿨습니다.

- 웹뷰 안에 [xterm.js](https://xtermjs.org) 터미널 표면.
- 익스텐션 호스트에 [node-pty](https://github.com/homebridge/node-pty-prebuilt-multiarch) 유사 터미널(pseudo-terminal).
- 그 pty에서 워크스페이스 폴더의 **대화형** Claude Code 세션을 그냥 돌립니다.

권한 프롬프트가 패널에 뜨고 거기서 `y/n`으로 답합니다. 후속 메시지는 같은 세션을 잇습니다. plan 모드가 됩니다. Claude Code 터미널이랑 똑같이 동작합니다. 패널을 닫거나 창을 리로드하면 pty 트리가 죽어서 유령 `claude` 프로세스가 안 남습니다.

**대가는 node-pty가 네이티브 모듈이라는 것.** VS Code가 도는 Node/Electron ABI에 맞아야 합니다. `@homebridge/node-pty-prebuilt-multiarch`를 정확한 버전으로 핀 고정해서 씁니다 — npm 패키지 안에 여러 ABI용 프리빌드 바이너리가 들어 있습니다. 그리고 프리빌드가 안 맞는 플랫폼에서는:

```js
// extension.js — require를 try/catch로 감싸고, 안 되면 runView를 headless로 자동 폴백
```

터미널 컴포넌트가 못 뜨면 Run 뷰가 알아서 예전 헤드리스 피드로 내려가고 한 줄 안내를 띄웁니다. Office 뷰는 영향 없습니다. 익스텐션은 여전히 활성화됩니다. `Agentyard: Open Claude Code Terminal` 커맨드는 일반 VS Code 터미널에 세션을 여는데 이건 항상 됩니다.

## v1.0.0 — 복붙, 첨부, 그리고 안 맞던 조직도

여기가 이번에 실제로 매일 쓰려고 만든 부분입니다. 제가 지금 Agentyard의 Run 뷰 안에서 Claude Code를 돌리며 이 작업들을 시켰는데, 두 가지가 걸렸습니다.

### 터미널 복사/붙여넣기

xterm.js는 클립보드 동작이 기본으로 없습니다. `Ctrl+C`는 그냥 SIGINT, `Ctrl+V`는 아무것도 안 합니다. 그래서 순수 함수 하나로 결정 로직을 짰습니다:

- `Ctrl/Cmd+C` — 선택 영역이 있으면 복사하고 키를 삼킴. **없으면 그대로 통과시켜서 SIGINT.** (이거 중요합니다. 터미널에서 Ctrl+C는 인터럽트여야 합니다.)
- `Ctrl/Cmd+V` / `Ctrl+Shift+V` / `Shift+Insert` — 클립보드 텍스트를 pty에 붙여넣기.
- 우클릭 — 선택 있으면 복사, 없으면 붙여넣기.

클립보드 접근은 웹뷰의 `navigator.clipboard`가 VS Code 버전·포커스에 따라 들쭉날쭉해서, 익스텐션 쪽 `vscode.env.clipboard`로 처리합니다.

### 파일과 이미지 첨부

Claude Code는 프롬프트에 적힌 파일 경로를 읽습니다. 이미지도 파일이면 읽습니다. 그래서 📎 버튼과 이미지 붙여넣기를 이렇게 처리합니다:

- **파일** — 📎 → 네이티브 파일 선택창 → 고른 경로를 입력줄에 삽입(제출은 안 함). 공백 있는 경로는 따옴표로 감쌈. 모든 경로는 하나의 빌더 함수를 거치고, 줄바꿈이 들어 있으면 거부합니다.
- **이미지** — 터미널이나 입력창에 붙여넣으면, 바이트를 워크스페이스 안 `.agentyard/tmp/`에 완전히 생성된 이름으로 씁니다(클립보드에서 온 텍스트는 파일명에 절대 안 들어감). 크기 제한이 있고, 워크스페이스 밖으로는 절대 안 씁니다. 그리고 그 경로를 입력줄에 넣습니다.
- `agentyard.keepAttachments`(기본 false)면 Run 뷰 초기화와 New thread 때 그 폴더를 비웁니다.

### 부서를 만들어놨는데 그 부서가 일하는 게 안 보였습니다

이게 이번 편에서 제일 저를 긁은 문제입니다.

분리된 프로젝트 저장소(agentyard 자신 포함)의 작업은 이렇게 굴러갑니다. 회사 세션의 Chief of Staff가 스펙을 쓰고, `repo-team-runner`를 호출합니다. 이놈이 그 저장소로 들어가서 **그 저장소 자체의 팀**(`project-lead` → `project-eng` → `release-check`) 역할을 인프로세스로 수행합니다. 회사는 설계와 검토, 저장소 팀은 빌드.

그런데 오피스 뷰는 이걸 이렇게 그렸습니다. `repo-team-runner`라는 떠돌이 스프라이트 하나가 일하고, agentyard 별관의 팀 자리(`project-lead`/`project-eng`/`release-check`)는 **텅 빈 채로**. 사무실을 보면 "부서는 노는데 러너만 일하는" 것처럼 보였습니다. 회사가 일하는 걸 보여주겠다는 익스텐션인데, 정작 그 팀이 일하는 게 안 보이면 만든 의미가 없습니다.

고친 방식(하드코딩 없이 데이터로):

- `state/company.db`의 `projects` 테이블에는 각 프로젝트의 `local_path`가 있습니다.
- 훅 스트림에서, 어떤 라이브 서브에이전트의 작업 디렉터리(`cwd`)가 어떤 프로젝트의 `local_path` 안이면 → 그 활동을 **그 프로젝트의 별관**에 귀속시킵니다.
- 별관 팀을 `working`으로 그리고, 러너의 현재 툴을 말풍선에, 간판에 `building…`. 떠돌이 러너 스프라이트는 제거.
- `company.db`가 없거나 `local_path`가 없거나 매칭이 안 되면 → 예전 동작 그대로. 경로 매칭은 슬래시 정규화 + Windows에서 대소문자 무시.

![별관이 빌드되는 중 — 팀 전체가 자리에 앉아 building… 간판을 달고 있음](이미지-자리표시자: annex-building.png)

이제 오피스를 보면 "agentyard 팀이 지금 v1.0.0을 빌드하고 있다"가 보입니다.

### 스크린샷에서 발견한 버그

마켓플레이스 스크린샷을 뜨다가, 씬 헤더에 `v0.4`가 하드코딩돼 있는 걸 봤습니다. 바깥 툴바는 `v1.0`으로 또 따로 하드코딩돼 있었고요. `package.json`의 버전을 익스텐션 호스트와 dev 서버 양쪽에서 `AY_CONFIG`로 주입하고, 캔버스 헤더와 툴바 둘 다 거기서 읽도록 바꿨습니다. 이제 하드코딩된 버전 문자열이 코드에 없습니다. 지금 당장만 맞추는 게 아니라 다음 버전에도 저절로 맞게.

## 배포

VS Code 마켓플레이스는 소스 폴더나 `.zip`이 아니라 `.vsix` 파일을 받습니다. 흐름은:

1. `package.json`의 `publisher`가 마켓플레이스에 만든 퍼블리셔 ID와 같아야 함.
2. `vsce package` → `agentyard-1.0.0.vsix`.
3. `vsce ls`로 패키지 내용물 확인 — `reports/`, `state/`, `.env`, 소스맵이 **안** 들어갔는지, node-pty 프리빌드 바이너리는 **들어갔는지**.
4. 관리 페이지에서 New extension → Visual Studio Code → `.vsix` 업로드.

첫 배포라 웹 UI로 올렸습니다. 다음부터는 `vsce publish` 한 방입니다.

`.vscodeignore`가 좀 까다로웠습니다. `node_modules/**`를 통째로 제외한 다음, node-pty 패키지의 런타임 조각만 `!` 패턴으로 다시 포함시킵니다 — 프리빌드 `.node` 바이너리와 conpty는 넣고, 디버그 심볼(`.pdb`, ~28MB)이나 TS 소스는 뺍니다.
